How PulseEngine Solves Concurrency

Core architectural guarantees powering zero overselling and ultra-low latency

1. Atomic Redis Lua Scripting

Every reservation request executes an atomic Lua script directly in Redis memory. If stock is available, it decrements in <1ms. If stock is zero, it immediately returns HTTP 409 without touching the SQL database.

2. Asynchronous BullMQ Queue

Successful Redis reservations return an HTTP 202 Accepted response in milliseconds and enqueue a background job. Users aren't held blocking on heavy database disk I/O, eliminating connection pool exhaustion.

3. ACID PostgreSQL Persistence

Worker processes consume queued jobs and execute an isolated prisma.$transaction with row locks. In case of any DB failure, Redis stock is safely rolled back via incrementEventStock.
